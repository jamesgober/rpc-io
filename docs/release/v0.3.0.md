# rpc-io v0.3.0 — Hardened, and Ready for Any Runtime

**The hardening release.** v0.3.0 fixes the findings of the 2026-10-13
audit (six were deferred or waived, with reasons; see below) and builds the
adapters a JSON-RPC engine needs in production around the 0.2 core: an
output path whose senders a slow peer cannot stall, deadlines that
fire on their own, an async adapter for any runtime, typed params through
`serde`, per-connection stats and `tracing`, LSP and MCP presets, a TCP and
Unix-socket server, and fuzz targets for every parser of untrusted input.
The default build still depends on `jsonx-lib` alone; every integration is an
optional feature, off by default.

## What is rpc-io?

The JSON-RPC 2.0 transport in the owner's net-collection: framing, the
envelope, correlation, cancellation, and the robustness fixes, once, for the
servers above it. lsp-lang 2.0 runs on rpc-io 0.2; mcp-io and the other
LexerSketch servers are planned to move onto it. Method semantics belong to
those protocol crates.
DAP shares only the Content-Length framing: its messages are not JSON-RPC,
so the engine does not serve them (0.2.0's "one transport for LSP, DAP, MCP"
said otherwise, and is corrected everywhere).

## What's new in 0.3.0

### A slow peer stalls no sender

In 0.2 the sink wrote under the endpoint's single lock, so a peer that
stopped reading froze every `Responder`, `Peer`, and `Call::cancel`, and the
endpoint's own next turn. `Queued` frames messages into a bounded queue and
writes them from its own thread; `outbox` does the same for an async task.
Past `QueueLimits` (64 MiB or 65,536 messages queued, or a writer that has
written nothing for 60 seconds, checked at each send) the connection closes.
Closing takes the lock only to close the queue: the closing thread waits for
the drain without it, for at most `close_timeout` (10 s), and every other
thread sees the connection closed at once. `serve` and `Server` use `Queued`.

```rust
use rpc_io::{Endpoint, Framing, QueueLimits, Queued, Router};

let sink = Queued::with_limits(std::io::sink(), Framing::ContentLength, QueueLimits::new().with_max_bytes(1 << 20))?;
let endpoint = Endpoint::new(sink, Router::<()>::new(), ());
endpoint.peer().notify("ready", ()).ok(); // queued; does not wait on the peer
# Ok::<(), std::io::Error>(())
```

### Deadlines that fire on their own

A request's deadline used to be checked only when a message arrived or
someone waited. Now the first deadline starts a timer thread for the
connection that ends due calls with `TimedOut` and sends the cancel
notification, with no traffic and no waiter. It holds only a weak reference
and stops when the connection closes; `Config::with_timer(false)` turns it
off.

### Async, on any runtime

`Call` is a `Future`, and dropping one before its outcome cancels the
request, as a dropped future should (`Call::detach` lets it run without a
waiter). `Endpoint::next_read`, `commit`, and `finish` are
`run` taken apart, so any reader (blocking, non-blocking, or `.await`ed)
feeds the endpoint with no copy. The `futures-io` feature adds
`Endpoint::run_async` and `Outbox::write_to` over `AsyncRead` and
`AsyncWrite`: smol and async-std directly, tokio through `tokio-util`'s
`compat`.

### Typed params and results

The `serde` feature: `Router::request_typed`, `notification_typed`,
`Params::deserialize`, `Peer::request_typed`, `Call::wait_typed`, and
`Responder::ok_typed`, for `lsp-types` and MCP schema crates. Params that do
not fit are `-32602`; values are read from the text the endpoint already
validated within its budgets.

### Protocol presets and helpers

`Config::lsp()` and `Config::mcp()` set the cancellation spelling, the
`initialize` gate, and the limits each protocol wants. MCP's turns batches
off (removed in its 2025-06-18 revision; `Limits::without_batches`) and serves
`ping` before `initialize` (`Gate::allow_request`). `Limits::network()` and
`Limits::strict()` cut every budget for remote peers. `Progress` sends MCP's
`notifications/progress` and `WorkDone` LSP's `$/progress` for the token a
request carries.

### Observability and an interceptor

`Endpoint::stats()` and `Peer::stats()` count traffic both ways, errors,
timeouts, evictions, cancellations, and panics, as plain integers under the
lock the endpoint takes anyway. The `tracing` feature adds a span per call
and events at documented levels, never `params`, results, or error `data`;
text the peer chose is clipped and escaped. `Router::intercept`
runs before every routed call: authorization, rate limits, an audit log.

### A server in a few lines

The `net` feature: `Server` accepts on a `TcpListener` (or, on Unix, a
`UnixListener`), serves one endpoint per connection with its own state, holds
connections to `max_connections`, and stops cleanly from a `Stopper`. It is
built for untrusted peers: a connection that leaves a message unfinished for
30 seconds (or sends nothing for 30 seconds after connecting), or stays idle
for 5 minutes with no traffic either way and nothing in flight, is closed, so
idle sockets cannot hold its slots; each
connection starts from `Limits::network()` and an 8 MiB outgoing queue; and
running out of descriptors pauses the accept loop instead of ending it.

### Fuzzed

Fuzz targets (`fuzz/`, cargo-fuzz) for Content-Length framing, newline
framing, message decoding, batch decoding, and a live endpoint. Their checks
run in every `cargo test` too, on random, JSON-shaped, and mutated bytes;
that harness found the one real bug of this cycle (below).

## Audit findings

The findings of the 2026-10-13 audit that were fixed, and the fuzz
harness's own (the deferred and waived ones follow the table):

| Severity | Finding | Fix |
|---|---|---|
| Medium | RPC-SEC-01: the sink wrote under the endpoint's single lock; a peer that stopped reading stalled every thread. | `Queued` and `outbox`; `serve` on `Queued`; `is_closed` reads a flag; closing drains outside the lock, bounded by `close_timeout`. |
| Medium | RPC-STD-01 / RPC-TST-01: no fuzz target for the parsers of untrusted input, against the DoD. | Five cargo-fuzz targets, and their checks in `cargo test`. |
| Medium | RPC-DOC-01 / RPC-DOC-02: "one transport for LSP, DAP, MCP"; a consumer list stated as fact. | Corrected everywhere: DAP shares the framing only; lsp-lang is the consumer. |
| Low-Medium | RPC-SEC-02: decoder and output buffers kept their peak size for the connection's life. | A shrink policy for the decoder, `Framed`, and the encoding buffer; geometric growth. |
| Low | RPC-COR-01: resuming `run` after a stop lost the messages read ahead. | The decoder lives in the endpoint; `run_with` for hand-off. |
| Low | RPC-COR-02: a request reusing an in-flight id got a second response under that id. | Answered under `null`, and reported. |
| Low | RPC-COR-03: deadlines did not fire while `run` blocked on input. | The timer thread. |
| Low | RPC-COR-04: `decode`'s "validated in full" was not true for an oversized batch. | The documentation names the early refusals. |
| Low | RPC-SEC-03: generous defaults amplify memory through `Params::parse`. | `Limits::network` and `strict`, `Server`'s default; the amplification documented. |
| Low | RPC-SEC-04: OS error text could reach the peer through `?`. | "the transport failed", the detail kept local. |
| Low | The blank line ending a header section counted against `max_header_bytes` in pieces but not whole (found by the fuzz harness). | It always counts, as documented. |
| Info | RPC-SEC-05, RPC-SEC-06, RPC-PERF-01, RPC-PERF-02, RPC-CQ-03, RPC-CQ-04, RPC-STD-06 | Held-message budget; `max_skip_bytes`; deferred lookups without copies; documentation; one step per decoder state; package excludes and no internal references; configurable read chunk and flush threshold. |

Deliberately not changed, with the reasons recorded in `dev/ROADMAP.md` and
`dev/DIRECTIVES.md`: lenient ids (RPC-COR-06) and `#[non_exhaustive]` message
structs (RPC-CQ-05), both breaking and decided with the 1.0 surface; loom
models (RPC-STD-05), moved to v0.9.0; `#![deny(warnings)]` (RPC-CQ-01), which
REPS requires.

## Dependency wiring

`jsonx-lib` 0.2 is still the only dependency of the default build. Optional,
each behind an off-by-default feature: `serde` and `serde_json` (`serde`),
`futures-io` (`futures-io`), `tracing` (`tracing`). `net` needs only `std`.
`jsonx-lib` has no `serde` support and no `ToJson`/`FromJson` yet; typed
params through its own traits stay planned for jsonx-lib 0.5 (D25).

## Breaking changes

None in the API: everything new is an addition, and the enums and structs
that grew variants or fields were already `#[non_exhaustive]`. Behavior that
changed, as a pre-1.0 minor release may:

- `serve` writes from a writer thread (`Queued`) and returns once its output
  is written; a peer that stops reading now closes the connection instead of
  blocking it.
- A request reusing an in-flight id is answered under `null`, not its id.
- Dropping a `Call` before its outcome cancels the request (the peer is
  told); `Call::detach` keeps it outstanding, as 0.2 did. `Call` is
  `#[must_use]`: `peer.request(..)?;`, which in 0.2 sent a request and
  ignored its answer, now warns, since it would cancel the request at once.
- `ErrorObject::from(Error::Io(_))` says "the transport failed", without the
  operating system's text.
- With `max_batch` 0, a batch is refused at its `[` with "batches are not
  accepted".
- A header section whose lines fit `max_header_bytes` only without its
  terminating blank line is now refused, as documented.

## Performance

The benchmarks (`cargo bench --bench bench`) and their latest figures are in
the README. They were measured on a machine under heavy background load,
where repeated runs differed by up to 40%; across back-to-back runs of 0.2.0
and 0.3.0 neither version was consistently faster. The new
`endpoint/run_100k_queued` benchmark puts the `Queued` path at about 80% of
the `Framed` one: the cost of a hand-off to the writer thread per batch.

## What's next

- **0.5.0**: Streamable HTTP, SSE, and WebSocket framings over the owner's
  net crates; typed params through jsonx-lib 0.5's `ToJson`/`FromJson`;
  Windows named-pipe serving.
- **0.9.0**: conformance suites backed by the fuzz corpus; loom models of the
  cancellation races.

## Installation

```toml
[dependencies]
rpc-io = "0.3"

# Framing, messages, and correlation only (no_std, alloc)
rpc-io = { version = "0.3", default-features = false }

# With the integrations
rpc-io = { version = "0.3", features = ["serde", "futures-io", "tracing", "net"] }
```

MSRV: Rust 1.85.
